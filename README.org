* BLEmacs

  王北洛's Emacs for Org schedule, C/C++ development, etc...

  版本：2.3.0 ｜ 平台：Linux、Windows ｜ 仓库：https://github.com/wbeiluo/beiluo-emacs

** 安装

  1. 下载配置文件
     #+BEGIN_SRC shell
     git clone https://github.com/wbeiluo/beiluo-emacs.git .emacs.d
     #+END_SRC

  2. 安装字体
     #+BEGIN_SRC shell
     sudo pacman -S ttf-maplemono ttf-maplemono-nf-unhinted ttf-lxgw-wenkai-mono ttf-jetbrains-mono ttf-nerd-fonts-symbols-common ttf-nerd-fonts-symbols-mono
     #+END_SRC

  3. 安装依赖软件
     #+BEGIN_SRC shell
     sudo pacman -S ripgrep pyright
     #+END_SRC

     | 工具    | 用途                        |
     |---------+-----------------------------|
     | ripgrep | consult-ripgrep / grep 搜索 |
     | pyright | Python LSP                  |
     | mpv     | EMMS 音乐播放               |

  4. 安装 LaTeX（org 导出与公式预览）
     #+BEGIN_SRC shell
     sudo pacman -S texlive texlive-langchinese
     #+END_SRC

  5. 启动 Emacs，首次启动自动从 ELPA（中科大镜像）安装全部插件

** 目录结构

  #+BEGIN_SRC
  init.el            启动引导：按固定顺序 require config/ 下的模块，最后加载 custom.el
  config/init-*.el   功能模块（34 个），每个以 (provide 'init-foo) 结尾
  agents/*.md        gptel-agent 自定义子代理定义（Markdown/Org，含 YAML 头）
  custom.el          Custom 生成，勿手写（不入库）
  logo.txt           启动界面 logo
  #+END_SRC

  新增模块 = 创建 =config/init-foo.el=（含 =(provide 'init-foo)=）并在 =init.el= 的
  require 列表中插入——模块不自动发现，加载顺序即依赖顺序（init-lib 提供公共库）。

  插件声明用 =use-package=，注意 =use-package-always-ensure= 为 nil：
  需要自动安装的包必须显式写 =:ensure t=。

** 嵌入式调试（C-c d）

  面向 STM32 等 ARM 工程的 dape 远程调试 + 构建集成。TI C2000 DSP 的调试在
  CCS/XDS 侧，这里覆盖其 gmake 工程的构建与代码阅读。

  依赖工具（按需安装）：

  | 工具                        | 用途                            |
  |-----------------------------+---------------------------------|
  | arm-none-eabi-gcc / gdb     | 交叉编译与调试（gdb >= 14.1）   |
  | openocd 或 JLinkGDBServer   | 目标板 GDBServer（二选一）      |
  | cmake / make                | 构建                            |

  调试走 GDB 原生 DAP（=gdb --interpreter=dap=），dape 直接复用 arm-none-eabi-gdb，
  不需要下载额外的调试适配器。

  | 按键        | 功能                                                     |
  |-------------+----------------------------------------------------------|
  | =C-c d d=   | 启动调试（stm32-openocd / stm32-jlink / gdb-remote）     |
  | =C-c d r=   | 重发初始命令（复位 + 烧写 + 复位）                       |
  | =C-c d x=   | 发送任意 GDB 命令（结果显示在 dape REPL）                |
  | =C-c d o=   | 启动 openocd                                             |
  | =C-c d j=   | 启动 JLinkGDBServer                                      |
  | =C-c d k=   | 停止 GDBServer                                           |
  | =C-c d b=   | 编译（自动识别 CMake / make / CCS gmake）                |
  | =C-c d c=   | cmake 配置（=cmake -S . -B build=）                      |
  | =C-c d f=   | 外部烧写（=embedded-flash-command=，默认 =make flash=）  |

  调试流程：=C-c d o= 启动 openocd（或 =C-c d j=）→ =C-c d d= 选 =stm32-openocd=
  attach → 会话首次停止自动执行初始命令（复位停住 → =load= 烧写 → 复位停住）→
  设断点、继续、查变量用 dape 默认键位（=C-x C-a= 前缀）。

  项目参数放工程根目录 =.dir-locals.el=（变量已声明安全，打开工程不询问）：

  #+BEGIN_SRC emacs-lisp
  ((nil . ((embedded-elf . "build/firmware.elf")     ; 不设则自动探测工程内 .elf
           (embedded-gdb-server-address . "localhost:3333")  ; 不设用配置默认端口
           (embedded-dape-init-commands . ("monitor reset halt"))  ; nil 禁用自动执行
           (embedded-flash-command . "make flash")
           ("*.cmd" . embedded-ti-cmd-mode))))        ; TI 链接命令文件
  #+END_SRC

  - openocd 参数在 =C-c d o= 时输入（如 =-f interface/stlink.cfg -f target/stm32f4x.cfg=），
    可在 =.dir-locals.el= 里用 =embedded-openocd-args= / =embedded-jlink-args= 固化
    （含设备型号，JLink 同理）。
  - 交叉 GDB 可用 =embedded-gdb-program= 覆盖（默认 arm-none-eabi-gdb，缺失时退回 gdb）。
  - TI CCS 的 gmake 工程识别根目录或 =Debug/= 下的 makefile；Windows 上可把
    =embedded-make-program= 设为 =gmake=。
  - 自动初始命令若失败（如未烧写过固件），用 =C-c d r= 重试；=C-c d x= 可手动执行
    =monitor reset halt= 之类的任意命令。

** gptel 使用速查

  只需回答三个问题：干什么（任务）→ 怎么干（自己指挥 / 外包 agent）→ 用什么档（默认跟任务）。

  | 我想…              | 怎么做                                            |
  |--------------------+---------------------------------------------------|
  | 随便问一句          | =C-c g s= 发送，=C-c g g= 开对话                    |
  | 做个任务            | 提示里写 =@任务名=，或 =C-c g m= 选 preset          |
  | 换口吻（不换任务）   | =C-c g m= → System message（default/chat/analyst） |
  | 让 AI 自己跑多步     | =C-c g A= 开 agent 会话（[Agent]/[Plan] 切换）      |
  | 把复杂任务外包出去   | 说「用 coder 做 XX」「用 analyst 审 XX」              |
  | 换模型档位          | =C-c g m= → 档位：fast / strong / reason / cheap    |

  preset 是会话内**单步**执行版；复杂任务外包给**自主执行**的分类 agent
  （定义在 =agents/*.md=）：=coder= 编程实现、=analyst= 分析诊断（只读）、
  =tech-researcher= 专业技术调研、=writer= 文字产出。任务 preset 只用只读工具
  （或不带工具），写/执行类工具只在 agent 层。

** 验证配置

  修改配置后可用 batch 启动自检（不打开图形界面）：

  #+BEGIN_SRC shell
  emacs --batch -Q --eval '(require (quote package))' --eval '(package-activate-all)' \
        -l ~/.emacs.d/init.el
  #+END_SRC

  exit 0 表示正常；报错会打印回溯到 stderr。注意开头的 =package-activate-all=
  不可省略（batch 模式不会自动激活 ELPA 包），且成功时无任何输出。
